# Editing and deployment review — 2026-09-14

## Editing

- The left sidebar contains image upload, Predict/Trained filters with counts, the image list, Remove all, current-image Download, Download all with its File name field, and a version line whose ? button opens the shortcut list. The right sidebar holds, top to bottom: Save/Load/collapse, Canvas (brush, zoom), Image (crop, width), Model (Train & predict), View (Labels and Prediction with their own opacity), and Paint (Uncertain only). Region finding was removed because the Random Forest trains on DINOv3 features only. Both sidebars collapse independently, and each hide button sits where its rail's show button was, so a second click closes what the first opened. Actions show state in the control itself (spinner, disabled), never as a status message, and busy buttons keep their size and label position. The one exception is Predicting… in the data bar under the image while training runs, placed there so nothing covers the image; a thin line along the bar's foot fills as the backend reports its stages, with the stage shares in config.js. A running prediction disables nothing; only exports and Save/Load/crop tasks do. Space during a prediction queues one more run, and Space with no new edits reuses the last training. Every key is drawn with the same keycap: the class chips (1–0, T), B + Wheel and Z + Wheel on the Canvas rows, Space on Train & predict, E, P and U on the switches, and Enter and Esc on Apply and Cancel while cropping. Touch screens, which have no keys, hide the keycaps (the class numbers stay, as the data bar uses them) and the ? buttons. The ? list repeats every shortcut, action first, in three groups (painting; model and view; moving around), and ? opens it with the left sidebar collapsed too, where the rail also keeps a ? button at its foot. The class row reads 1–9 / 0. Ctrl + wheel zooms, as does ⌘ + wheel on a Mac, and = works for + on opacity. [ and ] step the brush size, and F zooms back to fit. Zoom reads Fit at 1. The image sits centred in the free area, and a zoomed view grows with the zoom until it fills that area, so a wide image uses the whole stage when zoomed and the point under the pointer stays put once the view is full. Prediction and Uncertain only stay disabled, with a "Train & predict first" tooltip, until a prediction exists, and Uncertain only also stays off when the prediction has no uncertain pixels. Train & predict is disabled with "Prediction is up to date" once the shown prediction reflects every label. On the collapsed tools rail a ▶ button keeps training, with the same states, one click away, and a dashed-circle button under it turns Uncertain only on or off, filled while it is on, so the shaded image is never left unexplained. Applying or resetting a crop predicts the new image when prediction is on. The data bar names its source, Prediction or Labels, and moving a hidden layer's opacity (or pressing + or -) shows the layer. One list filter is always selected and switches to whichever list holds the selected image. Removing the selected image moves to the next one, which is predicted like a picked image once prediction is on; removing an unlabeled image leaves the prediction up to date, since only labels train the model. Remove all, removing a labeled image, and a crop or crop reset that would drop labels ask for confirmation first; in crop mode Apply (Enter, filled once a box is set) and Cancel (Esc) take the place of the crop buttons and Max width, so nothing moves, and the data bar keeps its room while hidden. Added files that cannot be decoded or are already listed are skipped with one alert naming them. Train & predict and Download all stay disabled, with a tooltip, until at least two classes are painted. Predictions start at 50% opacity. Save/Load/crop errors appear under the Save/Load buttons and clear on the next action. Max width is one setting, shown the same on every image, and applies on Enter. Between 769 and 1100 px wide both sidebars start collapsed so the image gets the room; at 768 px and below the image sits right under the palette, an open tools panel scrolls in the lower part of the screen so the image stays in view (its arrow points up to open and down to close), and the data bar puts the image name and size on their own line when they do not fit, and when the editor area is narrower than 600 px the label palette becomes two even rows, each item centred in its column (three below 340 px: 1–5, 6–0, then the eraser and clear buttons). Stepping between images keeps the previous image on screen until the next one is drawn. The interface is graphite on white, with color reserved for the ten classes; a black data bar under the image shows each class's pixel share, the image name and its working size.
- Uncertain only darkens everything outside the uncertain pixels while it limits the brush to them. Training labels render above it, including live brush strokes.
- Train & predict shows a spinner while a prediction runs and is highlighted, with a "Your latest labels are not trained yet" tooltip on it and on the rail's ▶, when labels changed since the last training. Clicking either returns focus to the image, so class keys keep working during the run. A prediction that finishes after you painted still shows, without your newest strokes, and the button stays highlighted. Prediction errors appear under it.
- Save downloads a versioned `.segment.json` containing original image bytes, pixel training labels, processing width, current image, selected class and brush size. Load validates the whole file before replacing the workspace (older files' region-finder settings and regions are ignored), then starts a fresh backend session for subsequent prediction. Previously enabled prediction is rebuilt from restored labels like any other run, so the editor stays usable meanwhile.
- Project files do not store RF/PCA objects, feature caches, prediction rasters, view toggles, zoom, or Undo/Redo history. Reopening can therefore incur fresh model extraction and may produce different predictions if the model/configuration changed, or if the earlier session PCA was fitted on a different initial image set. PNG/ZIP exports remain the way to retain a particular final prediction.
- Saving is manual. Unsaved edits trigger the browser's normal leave-page warning; this cannot protect against a crash. Files are limited to 256 MiB, with per-mask and aggregate decoded-pixel limits. Failed imports leave existing labels intact.

The proposed first-prediction button and one-class guidance are deferred. Space still starts training; the backend requires at least two labeled classes for a full prediction.

## Multiple users

Independent browser tabs obtain separate random session IDs. Each server session owns its training records, RF, PCA, parameters, feature caches and lock. Label deletion in one session does not affect another. Candidate model weights are shared; a runtime lock serializes its evaluation and token capture. Export jobs have unique paths and verify the owning session for status, cancellation and download.

Use **one backend worker** for the current implementation. Sessions and export jobs live in process memory, so requests distributed across multiple workers/replicas can receive session-not-found responses. FastAPI documents that worker processes [normally do not share memory](https://fastapi.tiangolo.com/deployment/concepts/#memory-per-process). This app needs shared storage and a deliberate model-worker/session routing design before horizontal scaling.

Build the frontend with `npm run build` in `frontend`, then serve the built app and `/api` on the same origin. For example, from `backend`, behind the deployment's reverse proxy:

```powershell
python -m uvicorn src.main:app --host 127.0.0.1 --port 8000 --workers 1
```

This command intentionally leaves external access to the reverse proxy. Do not use development reload for deployment.

Isolation does not guarantee capacity: concurrent RF fits each use all available CPU threads; GPU work queues behind the shared lock. Configured feature and raw-token caches can total about 1.3 GiB per session, excluding models, training images and temporary arrays. There is no global session or memory admission limit. Idle sessions expire after the configured hour and cleanup runs on session-store activity. A server restart loses backend state; users can reopen saved project files.

Session IDs provide separation, not user accounts or account-level authorization. A production service that needs authenticated access must supply that layer. With remote hosting, inference images are sent to that server; the local-only privacy description applies only to local hosting.

## Evidence and limits

- Frontend tests cover project round trips with all classes, unlabeled pixels, large instance IDs, immutable save snapshots, invalid input preserving existing labels, restored parameter-keyed proposals, stale prediction status and hover coordinates.
- Backend concurrent tests train opposite labels on the exact same image in two sessions, verify independent predictions, delete one session's training and verify the other stays unchanged.
- Export tests reject another owner's status/path/cancel requests and verify distinct paths.
- Separate session-store instances demonstrate why multiple workers cannot share sessions. This is not a multi-machine load test; no supported maximum simultaneous-user count has been measured.
- Verification: 84 backend tests, 76 frontend tests and the production frontend build pass. In-browser checks used a small image with known labels/regions and the real GPU/RF backend: project import, region hover, Updating… → Up to date, translucent Unclear, a visible Shift-brush correction, automatic retraining, and an actual downloaded project containing the new class label.
